# AniWatch

AniWatch — веб-платформа для поиска аниме, ведения личной библиотеки и просмотра серий. В проекте есть главная страница с подборками, каталог с фильтрами, страницы тайтлов, встроенный видеоплеер, аккаунты с облачной синхронизацией, пользовательские коллекции и комнаты для совместного просмотра.

> **Важно:** AniWatch не хранит и не раздаёт видеофайлы. Видеопотоки и часть каталожных данных предоставляют сторонние сервисы. Их доступность, качество и соответствие конкретному тайтлу зависят от внешних источников.

## Возможности

### Главная страница

- **Баннер «В центре внимания»** — выделяет тайтл, показывает жанры, год, статус, рейтинг и описание. Есть ручное переключение слайдов и автоматическая смена.
- **Продолжить просмотр** — показывает недавно открытые тайтлы и возвращает к сохранённой серии и позиции.
- **Лучшие всех времён / подборки** — состав списков приходит из AniLibria, затем каждый релиз сопоставляется с Shikimori по Shikimori ID; при отсутствии ID используется строгое совпадение названия и года. Карточки, русские названия, описания, жанры, рейтинги и постеры берутся из Shikimori.
- **Недавно вышло** — список свежих релизов AniLibria, сопоставленный с карточками Shikimori.
- **Жанровые переходы** — быстрые ссылки в каталог с выбранным жанром.
- **Правая колонка** — компактные подборки «Сейчас выходит» и «Популярное». На широком экране колонка прокручивается независимо от основного содержимого.

### Каталог

- Поиск по названию с задержкой ввода и подсказками.
- Фильтры по жанру, году, сезону, статусу, формату и минимальному рейтингу.
- Сортировка по доступным вариантам каталога.
- Постраничная загрузка результатов.
- Сброс всех фильтров.
- Параметры поиска и фильтров хранятся в URL, поэтому ссылкой на выбранную выдачу можно поделиться.
- Данные каталога загружаются из Shikimori. На главной AniLibria формирует списки подборок, а Shikimori предоставляет метаданные и постеры карточек. Несопоставленные релизы не подменяются похожими тайтлами; недостающие позиции в подборках добираются из Shikimori без повторов.

### Карточки и страница аниме

- Карточки показывают постер, название, рейтинг, статус и жанры.
- Быстрый переход к подробной странице тайтла.
- Добавление и удаление из избранного прямо на карточке.
- На странице аниме отображаются описание, оригинальное название, жанры, рейтинг, год, статус и количество эпизодов.
- Показывается список серий; доступные и ещё не вышедшие эпизоды различаются.
- Серии можно отмечать просмотренными и снимать отметку. Счётчик просмотренных серий обновляется сразу.
- Можно выбрать личный статус: «Смотрю», «Запланировано», «Просмотрено» или «Брошено».
- Есть пользовательская оценка тайтла, избранное и переход к просмотру.
- Поддерживаются связанные и похожие тайтлы, если внешний API возвращает данные.
- При наличии данных AniList на странице показывается трейлер.
- Следующая серия может отображаться с информацией о времени выхода, если расписание доступно от AniList.

### Личная библиотека

- **Избранное** — отдельная страница со всеми сохранёнными тайтлами.
- **Мои списки** — общий список и фильтрация по статусам просмотра.
- **История** — запоминает последнюю серию, позицию воспроизведения и скорость.
- **Прогресс серий** — сохраняет индивидуальные отметки просмотренных эпизодов.
- **Профиль** — показывает количество тайтлов в библиотеке, распределение по статусам, избранное, начатые тайтлы, отмеченные серии, среднюю пользовательскую оценку, прогресс завершения, часто встречающиеся жанры и недавнюю активность.
- Можно изменить отображаемое имя, акцентный цвет и аватар.
- Для гостя данные хранятся на устройстве; после входа доступна синхронизация с аккаунтом.

### Персональные рекомендации

- Главная страница показывает подборку уже с первого посещения: без истории используются популярные тайтлы Shikimori.
- По мере накопления оценок, избранного, статусов просмотра и прогресса система формирует профиль жанровых предпочтений.
- Высокие оценки усиливают соответствующие жанры, низкие — снижают их приоритет.
- Просмотренные, добавленные в библиотеку и ранее отклонённые тайтлы исключаются из повторной выдачи; для сопоставления источников учитывается MAL ID.
- У каждой карточки есть краткое объяснение рекомендации и действие «Не интересно».
- Для гостей отклонения хранятся локально; для авторизованных пользователей — в `anime_recommendation_feedback` с RLS и политиками доступа только к собственным строкам.
- Алгоритм работает без платной нейросети и не создаёт отдельную копию оценок: источником оценок остаётся `user_library`.

### Пользовательские коллекции

- Просмотр публичных коллекций сообщества.
- Создание коллекций с названием, описанием, обложкой и настройкой публичности.
- Добавление тайтлов из каталога в свою коллекцию и удаление их из неё.
- Редактирование и удаление собственной коллекции.
- Сортировка элементов по позиции добавления.
- Оценка публичных коллекций другими авторизованными пользователями.
- На странице коллекции показываются количество тайтлов, средняя оценка и число оценок.
- Автор не может оценивать собственную коллекцию.

### Совместный просмотр

- Создание комнаты и выбор тайтла.
- Генерация кода-приглашения; участники могут открыть ссылку или ввести код.
- Список подключённых участников через Supabase Realtime Presence.
- Чат комнаты в реальном времени через Broadcast.
- Синхронизация выбранного тайтла/серии и состояния воспроизведения: пауза, запуск, позиция и скорость.
- Для общей синхронизации встроенного видео все участники должны выбрать один и тот же поддерживаемый источник — AniLiberty или AnimeVost.
- Комнатные события и сообщения чата передаются как временные Broadcast-события, а не сохраняются как история сообщений в базе.

### Случайное аниме

Страница случайного выбора получает случайный тайтл из Shikimori и перенаправляет на его подробную страницу. Если внешний API недоступен или вернул некорректные данные, отображается сообщение об ошибке с возможностью повторить попытку.

### Резервная копия

- Экспорт локального состояния в JSON-файл.
- Импорт ранее созданной резервной копии AniWatch.
- Перед импортом запрашивается подтверждение, так как импорт заменяет текущие локальные данные.
- Проверяется формат и базовая структура файла.

### Установка как приложение

AniWatch поддерживает PWA:
- веб-манифест и иконки приложения;
- возможность установить сайт на главный экран поддерживаемого устройства;
- Service Worker кэширует оболочку приложения и локальные файлы;
- при отсутствии сети можно открыть ранее закэшированные страницы;
- внешние изображения и видеопотоки не сохраняются в офлайн-кэш.

## Страницы сайта

Все экраны — отдельные HTML-страницы. Параметры передаются через query string, а не через hash.

| Страница | URL | Назначение |
|---|---|---|
| Главная | `index.html` | Баннер, продолжение просмотра, подборки и жанры |
| Каталог | `catalog.html` | Поиск, фильтры, сортировка и загрузка результатов |
| Избранное | `favorites.html` | Сохранённые избранные тайтлы |
| Мои списки | `lists.html` | Библиотека со статусами просмотра |
| Коллекции | `collections.html` | Публичные и личные подборки; параметр `?id=...` открывает конкретную коллекцию |
| Вместе | `together.html` | Создание комнаты и присоединение по коду |
| Профиль | `profile.html` | Настройки, статистика и аккаунт |
| Случайное | `random.html` | Случайный выбор аниме |
| Страница тайтла | `anime.html?id=...` | Информация, серии, оценки и связанные тайтлы |
| Просмотр | `watch.html?id=...&ep=...` | Видеоплеер и список серий |

Старые hash-ссылки вида `index.html#title-12` обрабатываются функцией `legacyRedirect()` и перенаправляются на соответствующую страницу.

## Как устроен просмотр

Встроенный плеер находится в `js/core/streaming-player.js` и подключает источники по запросу пользователя.

| Источник | Реализация | Совместная синхронизация |
|---|---|---|
| AniLiberty | Поиск релизов по названию, выбор релиза и серии, HLS-поток | Да |
| AnimeVost | Поиск тайтла и получение потоков через Supabase Edge Function | Да |
| AnimeLib | Получение списка эпизодов по Shikimori ID и открытие страницы просмотра AnimeLib во встроенном iframe с внешней ссылкой на случай запрета встраивания | Нет |
| Kodik | Поиск по Shikimori ID или названию, выбор озвучки и эпизода, открытие embed-плеера | Нет |

Дополнительные функции встроенного плеера:
- выбор качества, когда источник предоставляет несколько вариантов;
- управление скоростью воспроизведения;
- восстановление позиции и скорости;
- сохранение текущего прогресса просмотра;
- автоматическая попытка перейти к резервному качеству при ошибке HLS;
- обработка буферизации и ошибок потока;
- переход к следующей серии после окончания текущей — с отметкой завершённой серии;
- встроенный просмотр на странице аниме и отдельная страница просмотра.

Горячие клавиши встроенного видео:
- `Space` или `K` — пауза / воспроизведение;
- `←` или `J` — назад на 10 секунд;
- `→` или `L` — вперёд на 10 секунд;
- `↑` / `↓` — громкость;
- `M` — выключить / включить звук;
- `F` — полноэкранный режим.

Набор доступных действий зависит от источника. AnimeLib требует Shikimori ID и использует API списка серий; встраивание страницы просмотра может быть запрещено политикой самого AnimeLib — в этом случае доступна внешняя ссылка. Kodik требует действующий API-токен: его можно ввести во вкладке Kodik плеера; токен хранится только в sessionStorage текущей вкладки и не включается в исходный код репозитория. Для совместной синхронизации Kodik пока не поддерживается.

## Аккаунт и хранение данных

### Гостевой режим

Основное состояние приложения хранится локально. Используются:
- **IndexedDB** — основное локальное хранилище состояния, если браузер его поддерживает;
- **localStorage** — резервное/совместимое хранение состояния под ключом `aw`;
- **sessionStorage** — временная передача уже загруженных карточек между страницами.

Сохраняются избранное, история, оценки, статусы списков, отметки серий, имя, акцентный цвет и другие пользовательские настройки. URL изображений не сохраняются как постоянные данные состояния.

### Аккаунт и облачная синхронизация

Авторизация и облачное хранение реализованы через Supabase:
- регистрация и вход по электронной почте и паролю;
- вход по имени пользователя и паролю через Edge Function;
- выход из аккаунта и восстановление сессии;
- профиль пользователя и аватар в Supabase Storage;
- синхронизация избранного, статусов, оценок, истории и просмотренных серий через таблицу `user_library`;
- синхронизация профиля через таблицу `profiles`;
- отложенная отправка локальных изменений в облако;
- восстановление и объединение локального и облачного состояния после входа.

Для работы облачных функций необходима корректно настроенная конфигурация Supabase, таблицы, политики доступа, Storage bucket и Edge Functions.

## Источники данных

### AniList

GraphQL API: `https://graphql.anilist.co`

Используется для:
- трендов, популярных тайтлов и онгоингов;
- постеров и баннеров по MAL ID;
- данных о тайтлах, баннерах и трейлерах.

Клиент `js/api/anilist.js` сериализует запросы, выдерживает интервал между ними, обрабатывает HTTP 429 и временные ошибки сервера, использует заголовки ограничения запросов и повторяет временно неудачные запросы.

### AniLibria

API v1: `https://anilibria.top/api/v1`

Используется для:
- недельного календаря релизов через `GET /anime/schedule/week`;
- отображения дня выхода, последней опубликованной на этой неделе серии и номера следующей серии;
- метки «Новая серия» на карточках тайтлов в «Моих списках» и «Избранном», если AniLibria сопоставляет релиз по MAL ID.

Расписание кэшируется в пределах вкладки на 10 минут. Изображения постеров не сохраняются Service Worker. Уведомления пока отображаются внутри сайта; push при закрытом PWA не реализован.

### Shikimori

API: `https://shikimori.io/api`

Используется для:
- каталожных метаданных и русских названий;
- поиска и фильтрации каталога;
- жанров;
- случайного выбора;
- подробной информации о тайтле;
- связанных и похожих аниме.

Постеры каталога не берутся из Shikimori: для карточек используется AniList по MAL ID. Если соответствие не найдено, показывается заглушка.

### Supabase

Используется для:
- авторизации и профилей;
- облачной библиотеки пользователя;
- аватаров;
- пользовательских коллекций и их оценок;
- отклонённых рекомендаций с отдельной RLS-защитой;
- Realtime-комнат, присутствия участников и чата;
- Edge Functions для входа по имени пользователя и получения потоков AnimeVost.

Если внешний каталог/API недоступен, приложение может использовать встроенные демонстрационные записи, но это не полноценная замена актуальному каталогу.

## Установка и запуск

Сборка не требуется. Нужен локальный HTTP-сервер: ES-модули и Service Worker не работают при открытии через `file://`.

Например, с Python:

```bash
python3 -m http.server 8000
```

Затем откройте:

```
http://localhost:8000
```

Либо используйте любой другой статический HTTP-сервер.

### Как добавить страницу

1. Создайте HTML-файл по образцу существующих страниц и укажите правильный `data-page`.
2. Добавьте страницу в `PAGES` в `js/core/router.js`.
3. Добавьте экран в контроллер `V` в `js/app.js` и при необходимости создайте шаблон в `js/pages/`.
4. Добавьте файл и необходимые модули в список `SHELL` в `sw.js`.
5. Увеличьте версию кэша Service Worker (`V`), чтобы клиенты получили обновлённую оболочку.
6. Запустите `node scripts/check-pages.mjs`.

## Проверки и публикация

Проект использует GitHub Actions:
- **Validate** проверяет согласованность страниц и обязательных файлов проекта.
- **Deploy** публикует статические файлы на GitHub Pages после изменения основной ветки.

Локальная проверка структуры:

```bash
node scripts/check-pages.mjs
node scripts/check-recommendations.mjs
```

Проверка структуры не заменяет ручное тестирование интерфейса, внешних API, авторизации, видеопотоков и Realtime-комнат.

## Ограничения

- AniWatch — клиентское приложение без собственного сервера каталога и видеохостинга.
- Работа каталога и метаданных зависит от AniList и Shikimori; календарь и метки новых серий — от доступности AniLibria API v1.
- Работа видеопотоков зависит от сторонних источников, доступности релизов, CORS, форматов потоков и ограничений браузера.
- Синхронизация просмотра поддерживается только для AniLiberty и AnimeVost при выборе одного источника всеми участниками комнаты.
- AnimeLib не поддерживает совместную синхронизацию; доступность iframe зависит от политики сайта.
- Офлайн-режим доступен только для закэшированной оболочки; каталог, авторизация, видео и актуальные данные требуют сети.
- Для полноценной эксплуатации Supabase должен быть настроен отдельно: схема базы, политики доступа, Storage и Edge Functions.
